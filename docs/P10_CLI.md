# P10 npm/Node CLI and source adapters

P10 exposes the deterministic audit/backlog engine through Node/npm without duplicating classifier or scoring logic. Source acquisition is isolated from analysis: Figma REST JSON and canonical snapshot JSON both normalize into the same `AuditNode`, then use the existing `buildAuditReport(...)` and `generateBacklog(...)` core.

## Commands

```bash
npm run audit:figma -- --url "https://www.figma.com/design/<file-key>/<name>?node-id=12-34"
npm run audit:figma -- --file-key "<file-key>" --node-id "12:34"
npm run audit:snapshot -- --input "/path/to/source-snapshot.json"
npm run backlog:generate -- --input "/path/to/audit-report.json"
```

Common options:

```text
--out <directory>
--previous-backlog <backlog.json>
--summary-only
--fail-on none|warning|error
```

`--summary-only` writes no output files and prints machine-readable JSON to stdout. `--fail-on` is intended for CI policy and returns exit code `10` when the requested active finding threshold is met.

## Figma credentials

P10 never accepts a raw token value as a command-line option and never writes credentials into snapshots, reports or backlogs.

Personal access token:

```bash
FIGMA_TOKEN="..." npm run audit:figma -- --file-key "<key>" --node-id "1:2"
```

OAuth access token:

```bash
FIGMA_OAUTH_TOKEN="..." npm run audit:figma -- --auth oauth --file-key "<key>" --node-id "1:2"
```

A custom environment variable may be selected with `--token-env <NAME>`. Personal tokens are sent through `X-Figma-Token`; OAuth tokens use `Authorization: Bearer ...`.

The caller is responsible for providing a token with the Figma file-content scope/permissions required for the requested file.

## Frame selection

A Figma URL may provide `node-id`. Otherwise use `--node-id`.

When only a file key/URL is supplied, P10 will select the document only if exactly one top-level `FRAME` exists across the returned pages. If multiple top-level frames exist, the adapter returns `AMBIGUOUS_FIGMA_FRAME` instead of guessing. Non-frame explicit node IDs fail closed.

## Canonical snapshot schema v1

Cloud audits emit `source-snapshot.json` alongside the report/backlog outputs. It is an owned, versioned offline interchange format:

```json
{
  "schemaVersion": 1,
  "capturedAt": "2026-09-10T00:00:00.000Z",
  "source": {
    "kind": "figma-rest",
    "fileKey": "...",
    "fileName": "...",
    "pageId": "...",
    "pageName": "...",
    "nodeId": "...",
    "nodeName": "...",
    "revision": "..."
  },
  "root": {
    "id": "...",
    "name": "...",
    "type": "FRAME",
    "geometry": {},
    "children": []
  }
}
```

The `root` is the same deterministic `AuditNode` shape consumed by the core engine. Snapshot loading validates schema version, timestamp, node fields and child-ID consistency before analysis. The same `capturedAt` value is reused as the audit report timestamp so a saved cloud snapshot can reproduce source-bound report/backlog output without injecting a new wall-clock timestamp.

Future plugin/adapter exporters may use source kinds `plugin-export` or `adapter-export` while preserving schema v1.

## Raw `.fig` files

P10 deliberately does **not** reverse-engineer Figma's proprietary local `.fig` format.

```text
npm run audit:snapshot -- --input /path/design.fig
→ UNSUPPORTED_FIG_LOCAL_FILE
```

Use one of:

- official Figma URL/file-key REST input; or
- canonical snapshot JSON generated by a supported adapter/exporter.

A future local-file route may be added only if a supported safe bridge exists.

## Outputs

Audit commands normally create:

- `audit-report.json`
- `audit-report.md`
- `backlog.json`
- `backlog.md`

`audit:figma` also creates:

- `source-snapshot.json`

`backlog:generate` creates only backlog JSON/Markdown.

The persistent CLI bundle can be built with:

```bash
npm run build:cli
node dist-cli/elementor-prep.mjs audit:snapshot --input /path/source-snapshot.json
```

Normal npm commands use `scripts/run-cli.mjs`, which bundles the same TypeScript CLI to an OS temporary directory with esbuild and executes it with the current Node runtime. This avoids requiring ts-node/tsx and retains Node >=20 support on Windows/macOS/Linux.

## Exit codes

- `0` — command completed and CI threshold was not met.
- `1` — unexpected internal CLI failure.
- `2` — command/input/schema/usage error, including unsupported raw `.fig` input.
- `3` — Figma credential/network/source acquisition failure.
- `10` — successful analysis, but `--fail-on` policy threshold was met.
