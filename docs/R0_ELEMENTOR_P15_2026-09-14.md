## Confirmed platform facts relevant to this slice

1. Elementor uses JSON as the documented structured page/template data format.
2. The documented general structure currently identifies data version `0.4` as the latest general structure version.
3. A document carries `title`, `type`, `version`, `page_settings`, and recursive `content`.
4. Modern layout content can use recursively nested `container` elements.
5. Widget elements use `elType: "widget"`, a `widgetType`, `settings`, and nested `elements` where supported.
6. `page_settings` and element `settings` are documented as an empty array when unset or an object when populated.
7. Responsive control data can be represented by device-suffixed setting keys such as `_tablet` and `_mobile` variants.
8. The Elementor Template Library supports importing template artifacts in JSON or ZIP form.
9. Atomic elements have a distinct evolving/versioned object shape (`e-*` element types plus their own element version and additional fields) and must not be silently treated as classic containers.
10. Website-template/kit ZIP import/export carries broader site/plugin/settings concerns and is therefore a separate contract from a single template JSON validator.

## Implementation decision for #303

Create a bounded, deterministic, read-only validator for a first target contract named `elementor-template-v0.4-container-v1`.

The validator will:

- accept document data version `0.4` only;
- validate modern `container` and `widget` structure recursively;
- require unique non-empty element IDs and non-empty widget types;
- accept only empty-array or object settings shapes;
- bound total elements and nesting depth before this code is ever exposed to untrusted artifact input;
- inventory widget types without implying those widgets are generatable or installed;
- reject legacy `section`/`column`, Atomic `e-*`, unknown element types and malformed structures with explicit issue codes.

The validator intentionally will not interpret arbitrary Elementor control values yet. Preserving settings as opaque JSON avoids inventing undocumented control semantics and keeps later widget mappings isolated/versioned.

## Safety and product boundary

This R0 record and #303 implementation do not prove Elementor import compatibility. They add no network access, WordPress authentication, target-site mutation, P14 Figma mutation, Pro entitlement inference, Atomic generation or production-acceptance authority.

A later P15 slice must generate a bounded artifact from an accepted neutral/source mapping, validate it with this or a successor contract, and then retain real Elementor import evidence before any import-success claim is made.
